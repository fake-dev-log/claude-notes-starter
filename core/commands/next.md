# /next $ARGUMENTS

세션 시작에 "다음 뭐 하지"를 묻지 않기 위한 커맨드. 큐 = `~/notes/queue.md`, 형식은 `~/notes/README.md`. 큐는 **순서**이지 상태가 아니다 — 착수 전에 실제 상태(티켓·PR·코드)를 한 번 본다.

**여러 세션이 같은 큐를 본다.** 그대로 두면 모두 같은 `▶ 지금` 을 집는다. 그래서 보기는 `claim.py show` 로 하고(다른 세션이 착수한 항목은 `🔒` 로 빠진다), 손대기 시작할 때 `/next claim` 으로 표시한다. 기계 부분 = `python3 ~/.claude/notes-kit/claim.py` — 큐 파싱·게이트·착수 판정은 스크립트가, 순서·문구 판단은 내가 한다.

## 프로젝트 결정
인자 > cwd 의 git 루트 디렉터리명 > 큐에 절이 하나뿐이면 그것 > 아니면 `all`.

## `/next` · `/next <프로젝트>` — 다음 작업 (읽기 전용)
1. `date +%F` 로 오늘을 잰다.
2. `python3 ~/.claude/notes-kit/claim.py show <프로젝트>` 출력을 그대로 보여 준다. **`▶ 지금` 이 착수 대상**이다. `🔒 … (세션 이름)` 은 다른 살아 있는 세션이 착수 중이라 뺀 것, `✋` 는 이 세션이 착수한 것, `⏳` 는 게이트(`⏰ MM-DD`) 전이다. 큐를 직접 읽어 `▶ 지금` 을 따로 고르지 않는다 — 착수 표시를 못 본다.
3. 오늘·어제 daily(`~/notes/daily/`) 의 그 프로젝트 절에서 `[이월]` 줄 중 큐에 없는 것을 "큐에 없음" 후보로 보여 준다. 넣을지는 사용자가 정한다.
4. `▶ 지금` 이 없으면 가장 이른 ⏰ 를 알리고, 그 사이 할 것은 `## 보류` 에서 고른다 — **지어내지 않는다.** 비어 있으면 비어 있다고 말한다.
5. 사용자가 착수를 정하면 **먼저 `/next claim`**(아래) 한 뒤 그 항목의 실제 상태를 확인하고 시작한다. 이미 끝난 것이면 `/next done` 으로 지우고 다음 항목으로.

## `/next all`
`python3 ~/.claude/notes-kit/claim.py show --all` — 프로젝트마다 `▶ 지금` 한 줄 + 가장 이른 게이트 한 줄.

## `/next claim <키|제목 머리|번호>` · `/next release <…>` — 착수 표시
- **큐 항목에 손대기 시작하면 먼저** `claim.py claim <프로젝트> <키|제목 머리|번호>`. 다른 세션의 `show` 에서 그 항목이 `🔒 <이 세션 이름>` 으로 보이고 `▶ 지금` 에서 빠진다. 큐 파일·git 은 안 건드린다.
- 항목은 번호가 아니라 **티켓 키, 없으면 제목 머리(` — ` 앞)** 로 식별된다 — 다른 세션이 큐를 다시 매겨도 표시가 따라간다. 번호로 줘도 되지만 그 순간의 큐에서 키/제목으로 바뀐다. 제목 머리를 고치면 표시가 떨어진다 — 고친 뒤 다시 claim.
- exit 3 = **다른 살아 있는 세션이 착수함**(stderr 에 세션 이름) → 그 항목은 하지 말고 `show` 에서 다음 항목을 고른다. 그 세션이 끝난 게 확실할 때만 사용자에게 묻고 `--force`.
- exit 4 = 세션 신원(`CLAUDE_CODE_SESSION_ID`·`CLAUDE_PID`)이 없다 — Claude Code 의 Bash 도구 밖에서 부른 것이다.
- 표시는 **이 세션이 살아 있는 동안만** 유효하다. 세션을 끝내면 release 를 안 해도 풀린다. 중간에 그만두면 `claim.py release <프로젝트> <…>`.
- 큐 줄에 `🔒` 를 손으로 쓰지 않는다 — 커밋이 생기고, 세션이 죽어도 안 풀린다.

## `/next add [프로젝트] "내용"`
- 번호 항목으로 절 끝에. 위치 지정(`--top`, `--after 2`)이 있으면 번호를 다시 매긴다. 프로젝트 절이 없으면 `## 보류` 앞에 만든다.
- 게이트가 있으면 `⏰ MM-DD` 를 항목 줄에.
- 절이 30줄을 넘기면 넣기 전에 낡은 항목을 `## 보류` 로 접는다.

## `/next done <키|제목 머리|번호>`
1. **먼저** `claim.py done <프로젝트> <…>` — 착수 표시를 풀고 **지울 줄 원문**을 출력한다(줄을 먼저 지우면 항목을 못 찾는다).
2. 출력된 그 줄을 큐에서 지우고 번호를 다시 매긴다. 번호로 짐작해 지우지 않는다 — 다른 세션이 그사이 번호를 바꿨을 수 있다. 남은 잔여가 유효하면 `- 잔여:` 로 옮긴다(버리지 않는다).

## `/next sync [프로젝트]` — 티켓·daily 대조 (쓰기, 선택)
티켓 시스템과 큐를 맞춘다. **Jira MCP(예: claude.ai Atlassian 커넥터)가 없으면 1·2 는 건너뛰고 3만 한다.** 프로젝트 절에 `> jql:` 줄이 없어도 1만 하고 2는 건너뛴다.
1. 그 절의 번호 항목에 적힌 티켓 키를 모아 `key in (…)` 로 상태를 조회한다(`fields: ["status","summary"]`). **Done 인 키는 큐에서 지운다**(남은 잔여가 유효하면 `- 잔여:` 로).
2. `> jql:` + `AND created >= "<synced 날짜>"` 로 **그 뒤 생긴 티켓**을 뽑아 "미배치" 목록으로 보여 준다. 큐에 넣을지는 사용자가 정한다 — 자동으로 넣지 않는다.
3. 어제·오늘 daily 의 그 프로젝트 절에서 `[이월]` 줄 중 큐에 없는 것을 후보로 보여 준다. 넣을 때는 daily 문장을 복사하지 말고 한 줄로 줄인다.
4. `> synced:` 를 오늘로 고친다(없으면 헤딩 바로 아래에 만든다).

결과가 큰 파일로 떨어지면 `jq` 로 `key`·`status.name`·`summary` 만 뽑는다. 전수 조회는 하지 않는다 — 항상 `key in` 이나 `created >=` 로 좁힌다.

## 마무리
쓰기(`add`·`done`·`sync`)를 했고 `~/notes` 가 git repo 면 `git add queue.md && git commit -m "queue(<프로젝트>): <한 줄>"` 을 확인 없이. 읽기는 커밋하지 않는다.

## 하지 않는 것
- 큐에 실측·근거를 길게 적지 않는다 — 그건 daily 의 몫. 큐 한 줄은 **다음에 뭘 하는지**만.
- 세션 시작에 자동 실행되지 않는다. 필요할 때 친다.
- `claim`·`release` 는 커밋하지 않는다 — 착수 표시는 노트가 아니라 `~/.claude/notes-kit/claims/` 에 있다.
