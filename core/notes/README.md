# notes

Claude Code 가 쓰고, 사람과 다음 세션의 Claude 가 읽는 노트. Obsidian 으로 연다.

```
daily/YYYY-MM-DD.md   그날의 서사. 프로젝트별 ## 헤딩 아래 번호 항목 (/log 가 쓴다)
queue.md              프로젝트별 다음 할 일 순서 (/next 가 읽고 쓴다)
lessons/              틀렸다가 실측으로 정정한 것만. 제목은 규칙 문장 (/log --lesson)
```

## daily 형식

```markdown
---
type: daily
date: 2026-09-16
---

## <프로젝트>
1. **<티켓키> <제목> — 결과 한 토막**          ← 제목 줄. 90자 안. 굵게.
   - 🔴 판정을 뒤집은 실측 · 조용히 실패하는 지점 · 다음 사람이 밟을 함정
   - ⚠️ 내가 틀렸다가 고친 것 · 미검증으로 남은 축
   - 🟢 싸게 끝난 판별법 (다음에 재사용)
   - [이월] 아직 안 한 것 ⏰ 09-20
```

- 제목엔 **무엇을** 했는지, 세부엔 **왜 그렇게 됐는지와 근거 수치**. 커밋 로그 복사 금지.
- `[이월]` 은 큐에도 한 줄로 들어간다. daily 는 서사, 큐는 순서.

## queue.md 형식

```markdown
## <프로젝트>
1. 다음에 할 것 한 줄 ⏰ 09-20      ← ⏰ 는 그 날짜 전엔 뽑지 않음
2. 그다음
- 잔여: 티켓 없는 작은 것

## 보류
- 당분간 안 할 것
```

프로젝트 절은 30줄을 넘기지 않는다. 넘치면 `## 보류` 로 접는다.

착수 표시(어느 세션이 어떤 항목을 잡았나)는 큐에 쓰지 않는다 — `/next claim` 이 `~/.claude/notes-kit/claims/` 에 두고, 세션이 끝나면 저절로 풀린다. 항목은 티켓 키, 없으면 제목 머리(` — ` 앞)로 식별되니 제목 머리는 짧고 고유하게 쓴다.

티켓 시스템(Jira)을 쓰는 프로젝트는 헤딩 바로 아래에 인용 줄 두 개를 둘 수 있다 — `/next sync` 가 읽는다. 없어도 된다.

```markdown
## <프로젝트>
> jql: project = ABC AND assignee = currentUser() AND statusCategory != Done
> synced: 2026-09-30
1. ABC-12 다음에 할 것
```

## 규칙

- 세션에서 실제로 관측한 것만 쓴다. 지어내지 않는다.
- 로컬 경로(`/Users/…`), 토큰·웹훅 URL·비밀번호·고객 개인정보는 쓰지 않는다.
