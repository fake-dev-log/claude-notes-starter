# /scrum $ARGUMENTS

인자: `am` | `pm` | `weekly`, 선택 `--post`(Slack 보고까지). `--post` 가 없으면 노트만 정리한다.

노트: `~/notes` (형식 정본 `~/notes/README.md` — 먼저 읽는다. `## 스크럼 설정` 절에 채널·레포 위치가 있다). 오늘 파일: `daily/YYYY-MM-DD.md`.
**외부 조회(Slack·Jira·캘린더)는 MCP 가 있을 때만 한다.** 없거나 실패하면 그 입력은 "미조회" 라고 적고 나머지로 진행한다 — 조회 못 한 것을 추측으로 채우지 않는다.

## 공통 준비
1. `date "+%F %a %H:%M"` 로 오늘을 잰다(추측 금지). **출근일** = 월~금. 캘린더 MCP 가 있으면 공휴일 캘린더를 조회해 공휴일도 뺀다.
2. **어느 daily 에 쓰나** — 기준은 명령을 친 시각이 아니라 **작업한 시각**(커밋·메시지·티켓 타임스탬프)이다. 19시 이후에 한 작업, 주말·공휴일에 한 작업은 **다음 출근일 daily** 에 쓴다(금요일 밤 → 월요일). 주말·공휴일 daily 파일은 만들지 않는다.
3. 직전 출근일 daily 와 오늘 daily 를 읽는다. `[이월]`·`[진행]` 항목을 모은다. 큐(`~/notes/queue.md`)의 프로젝트별 `▶ 지금` 후보도 본다(`/next all` 과 같은 규칙).
4. 캘린더 MCP 가 있으면 오늘 일정(`am`·`pm`) 또는 이번 주·다음 주 일정(`weekly`)을 조회한다. 회의 링크·비밀번호는 옮기지 않는다 — 시간·제목·상대만.

## `am` — 아침
입력: 큐의 `▶ 지금`, 어제 이월, (Jira MCP) 나에게 배정된 열린 이슈 `assignee = currentUser() AND statusCategory != Done ORDER BY updated DESC`, (Slack MCP) 어제 저녁 이후 나를 멘션한 메시지·DM, 설정의 레포 위치에서 어제 이후 내 커밋(`git log --since=yesterday --author="$(git config user.email)"`).
출력: 오늘 daily 맨 위에 `## 아침 스크럼` 절. 이미 있으면 덮지 말고 갱신한다.
- **오늘 우선순위 최대 3개** — 한 줄 = 한 프로젝트(마감이 같다고 다른 프로젝트를 한 줄에 묶지 않는다). 프로젝트 태그 + 티켓 키 + **왜 지금인지** 한 줄. 근거 없는 항목은 넣지 않는다. 상한 3 은 목표가 아니라 상한이다.
- **개인** — 회사 일이 아닌 계획이 있으면 이 줄에 따로(`--post` 에는 안 나간다)
- **이월** — 어제 못 끝낸 것
- **막힌 것 / 누구에게 물을 것**
- **회의** — 오늘 일정(시간·제목·상대)

## `pm` — 저녁
입력: 오늘 커밋(설정의 레포 위치 전부), (Jira MCP) 오늘 내가 전이·코멘트한 이슈, (Slack MCP) 오늘 내가 쓴 메시지·스레드, 오늘 daily 에 이미 적힌 것(`/log` 가 쓴 것), 아침 우선순위, 오늘 일정.
출력:
1. 오늘 daily 의 프로젝트 헤딩 아래에 **한 일**을 채운다. 항목 형식은 `/log` 와 같다 — 제목 한 줄(굵게, 90자 안) + 들여쓴 세부 불릿. **이미 있는 항목은 유지·보강만** 하고 새 번호를 붙이지 않는다. 빈 헤딩은 만들지 않는다. 회사 일이 아닌 것은 `## 개인`.
2. 맨 아래 `## 저녁 스크럼` 절:
   - **완료 / 진행 / 이월** — 아침 우선순위와 대조
   - **결정된 것** — `~/notes/RESOLVER.md` 가 있으면 `decisions/` 초안을 만들고 링크, 없으면 한 줄로
   - **배운 것·실수** — 있으면 `lessons/` 노트(형식은 `/log` 5절)를 만들고 링크
   - **내일 첫 일**
3. 캘린더에 있는데 daily 에 흔적이 없는 회의가 있으면 한 줄이라도 남길지 묻는다. 결정·액션이 있는 회의는 RESOLVER 가 있으면 `meetings/YYYY-MM-DD 제목.md` 로 분리한다.

## `weekly` — 주 마지막 출근일 저녁
이번 주 출근일 daily 전부를 읽어 `weekly/YYYY-MM-DD 주간.md` 를 만든다. **두 층으로 쓴다**:
1. **붙여넣기 층 (맨 위)** — 팀 주간 회의록에 그대로 옮길 초안. 프로젝트별 2~5개의 **짧은 명사구**, 티켓 키·수치·링크·굵게 없이. 다음 주 계획 2~5줄. 팀에 알릴 특이사항(장애·외부 일정·휴가)만. 형식은 직전 weekly 의 붙여넣기 층이 있으면 그것을 따른다. **회의록 도구에 직접 쓰지 않는다** — 사람이 옮긴다.
2. **근거 층 (`---` 아래)** — 한 일(상세, 티켓 키 포함) · 프로젝트별 숫자와 daily 링크 · 특이사항 · 다음 주 계획(캘린더 반영 — 다음 주 첫 `am` 이 읽는다) · 리스크.
`## 개인` 항목은 회사 일과 섞지 않고 끝에 따로 둔다.

## `--post` — Slack 보고 (`am --post` / `pm --post`)
채널은 `~/notes/README.md` `## 스크럼 설정` 의 `채널:`. 비어 있으면 묻고, 답을 그 줄에 적어 둔다.
**형식은 내가 그 채널에 올려 온 것을 따른다** — 처음 한 번, 그 채널에서 내가 쓴 최근 게시물 3~5건을 검색해(`from:me in:#채널`) 머리말(날짜 표기·꺾쇠 제목)·프로젝트 구분·번호 방식을 읽고, 설정의 `형식:` 줄에 한 줄로 요약해 둔다. 이후엔 그 줄을 따른다. 게시물이 없으면 아래 기본형.

**am --post** — `am` 을 먼저 끝낸 뒤 우선순위를 최대 4개로 압축한다. **회사 일만** — `개인` 줄은 넣지 않는다. 일정은 **내 것만**, 오늘 있는 회의·배포 창·(하루 전) 내 휴가일 때만 붙인다. 남의 일정은 넣지 않는다.
```
MM/DD

<우선순위>
1. …
2. …
```

**pm --post** — `pm` 을 먼저 끝낸 뒤, **본문은 손으로 쓰지 않고 렌더러로 뽑는다**:
`python3 ~/.claude/notes-kit/scrum_render.py ~/notes/daily/YYYY-MM-DD.md`
렌더러는 프로젝트 절의 **제목 줄만** 평문으로 내고(세부 불릿·`## 개인`·스크럼/회의 절 제외, 굵게·wikilink·`[이월]` 제거), 제목이 90자를 넘으면 stderr 로 경고한다. 경고가 있으면 **daily 를 고친 뒤 다시 뽑는다** — 렌더 결과를 손으로 다듬어 보내지 않는다. 머리말(`MM/DD`, `<Daily Report>` 등)만 형식에 맞게 앞에 붙인다.

⚠️ Slack MCP 의 전송 도구는 본문을 **markdown 으로 변환**한다 — 번호 목록 바로 다음 줄(빈 줄 없이)의 프로젝트 이름은 앞 항목에 붙고, 다음 목록의 `1.` 이 앞 번호에 이어진다. 렌더러가 프로젝트 사이에 빈 줄을 넣는 이유다. 지우지 않는다.

**게시 절차 (확인 후에만 전송)**
1. 초안 전문을 코드 블록으로 보여 준다. 오늘 이미 같은 종류의 내 게시물이 있으면 알리고 중복 게시 여부를 묻는다.
2. 사용자가 OK 하면 전송. **확인 없이 보내지 않는다.**
3. 전송 직후 그 채널 최근 1건을 다시 읽어 **프로젝트마다 번호가 1부터 다시 시작하는지** 본다. 번호가 이어지면 변환에 깨진 것이다 — MCP 로는 수정·삭제가 안 되니 알리고(삭제는 사람 몫) 재게시 여부를 묻는다.
4. 게시 링크를 오늘 daily `## 스크럼` 절에 한 줄(`- pm 보고: <링크>`)로 남긴다.

## 마무리
- `~/notes` 가 git repo 면 이번에 만든·고친 파일만 `git add` 해서 `git commit -m "YYYY-MM-DD scrum am|pm|weekly"` 를 확인 없이 한다(`git add -A` 금지). 원격이 있으면 push.
- 결과를 한 줄로: 어느 파일에 무엇을, 미조회 입력이 있었으면 무엇이었는지.
- 절대: 조회하지 못한 사실을 지어내지 않는다.
