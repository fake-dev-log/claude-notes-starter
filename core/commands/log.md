# /log $ARGUMENTS

**방금 끝난 작업 하나**를 `~/notes/daily/` 에 남긴다. 세션 끝에 기억이 살아 있을 때 쓴다. 형식 정본은 `~/notes/README.md` — 먼저 읽는다.

## 인자
- 비우면 이번 세션에서 한 작업을 자동 판정. `PROJ-123` 처럼 티켓·주제를 주면 그것만.
- `--lesson` — 교훈 노트만 쓴다(아래 5). daily 는 기존 항목 끝에 `→ [[제목]]` 링크만 붙인다.

`/scrum pm` 을 쓰는 날에도 `/log` 는 그대로 친다 — 작업 직후의 기록이 저녁 정리보다 정확하다. `pm` 은 있는 항목을 보강만 한다.

## 1. 날짜
`date "+%F %a %H:%M"` 로 잰다(추측 금지). **19시 이후에 한 작업은 다음 평일 daily** — 금요일 밤 → 월요일. 파일은 `~/notes/daily/YYYY-MM-DD.md`, 없으면 frontmatter(`type: daily`, `date:`)만 넣어 만든다.

## 2. 어디에
- 헤딩은 `## <프로젝트>`. 프로젝트 이름은 인자 > cwd 의 git 루트 디렉터리명 > `기타` 순으로 정한다. 큐(`~/notes/queue.md`)에 이미 같은 프로젝트 절이 있으면 그 이름을 그대로 쓴다.
- 헤딩이 없으면 파일 끝에 만든다. 이미 그 프로젝트에 같은 작업 항목이 있으면 **새 번호를 붙이지 말고 그 항목을 보강한다.**
- 추가만 한다. 다른 항목은 지우거나 고치지 않는다.

## 3. 무엇을 — 제목 한 줄 + 세부 불릿
```
1. **PROJ-123 주문 목록 페이지네이션 — 커서 방식으로 교체, prod 배포**
   - 🔴 offset 이 느린 게 아니라 정렬 컬럼에 인덱스가 없었다 — 실측 2.1s → 40ms
   - 배포 `a1b2c3d`, 마이그레이션 1건
   - ⚠️ 리뷰 지적 "캐시 추가"는 기각 — 인덱스만으로 충분, 캐시는 무효화 비용이 더 큼
   - [이월] 모바일 앱 쪽 호출 방식 확인 ⏰ 09-20
```
- **제목**: 티켓키 + 제목(또는 작업 요약). 결과가 한 토막으로 붙을 땐 ` — ` 뒤에. 90자 안. 근거·수치는 제목에 넣지 않는다.
- **세부**: 무엇을 했는지가 아니라 **왜 그렇게 됐는지**와 근거 수치. 🔴 판정을 뒤집은 실측·조용히 실패하는 지점 / ⚠️ 틀렸다가 고친 것·미검증 축 / 🟢 싸게 끝난 판별법.

**반드시**: 실측치와 분모("0건/8,849") · 배포했으면 좌표(커밋 SHA 등) · **안 한 결정과 그 이유**(기각한 대안은 나중에 되살아난다) · 남은 관찰은 `[이월]` + `⏰ MM-DD`.
**쓰지 않을 것**: 커밋 로그를 풀어 쓴 것(git 이 갖고 있다) · "구현했다·테스트했다" 같은 결과 없는 진술 · 로컬 경로·토큰·PII.

## 4. 이월 → 큐
`[이월]` 이 생겼으면 `~/notes/queue.md` 의 그 프로젝트 절에 **한 줄로 줄여** 추가한다(daily 문장 복사 금지). 끝낸 작업이 큐에 있었으면 그 항목을 지우고 번호를 다시 매긴다. 규칙은 `/next` 와 같다.

## 5. 교훈 노트 (해당할 때만)
**내가 틀렸다가 실측으로 정정한 것**이 있으면 `~/notes/lessons/YYYY-MM-DD 제목.md`. 제목은 **규칙 문장**(`…는 …이다` / `…하라`)이지 사건 이름이 아니다. 구조: frontmatter(`type: lesson`, `date`) → `# 제목` → `## 실측` → `## 규칙` → `관련: [[YYYY-MM-DD]]`. daily 항목에서 `[[제목]]` 으로 건다. 같은 뿌리의 교훈이 있으면 새로 만들지 말고 `## 실측 2` 로 덧붙인다. 교훈이 없으면 만들지 않는다.

## 6. 사람·프로젝트·결정 (`~/notes/RESOLVER.md` 가 있을 때만 — entities 모듈)
없으면 이 절 전체를 건너뛴다. 있으면 먼저 읽고, 이번 작업에서 **새로 생긴 사실**만 옮긴다:
- 확정된 결정(무엇을·왜·기각한 대안) → `decisions/YYYY-MM-DD 제목.md` 초안, daily 항목에 `→ [[제목]]`.
- 사람·프로젝트에 대한 새 사실 → 그 페이지 `## 타임라인` 에 `- YYYY-MM-DD — 한 줄 ([[YYYY-MM-DD]])`. 페이지가 없으면 RESOLVER 의 "만들 조건"에 맞을 때만 만든다.
- 기존 사실을 뒤집는 것이면 RESOLVER 의 정정 절차를 따른다(옛 줄을 지우지 않고 표시).

## 7. 마무리
- `~/notes` 가 git repo 면 `git add daily lessons queue.md` (+ 6에서 만든·고친 파일) `&& git commit -m "YYYY-MM-DD <티켓|주제> 기록"` 을 **확인 없이** 한다. `git add -A` 는 쓰지 않는다 — 다른 세션이 쓰던 파일이 딸려 들어간다. 원격이 있으면 push. repo 가 아니면 건너뛴다.
- 결과를 한 줄로 알린다: 어느 파일의 어느 절에 몇 줄, 큐 변경 여부.
- 워크스페이스 메모리에 남길 함정(다음 세션의 Claude 가 밟을 것)이 있으면 그것도 쓴다 — 문장은 daily 와 다르게. 메모리는 함정 색인, daily 는 서사.
- 절대: 세션에서 실제로 관측하지 않은 것을 쓰지 않는다.
