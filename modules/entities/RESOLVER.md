# RESOLVER — 이 내용은 어디로 가나

Claude 가 노트에 쓰기 전에 읽는 라우팅 규칙. 위에서부터 묻고, **첫 번째로 "예"인 곳이 집**이다. 한 내용은 한 곳에만 두고 나머지는 `[[링크]]` 한다.

**0. 이미 있는 사실과 어긋나는가?** → 라우팅보다 **정정이 먼저**다(아래 정정 절차).

1. **특정 사람에 대한 사실인가?** (역할·담당·선호·"이 사람이 이렇게 말했다") → `people/이름.md`
2. **프로젝트의 개요·상태·설계·열린 문제인가?** → `projects/<slug>/README.md`(개요·상태·타임라인), 긴 설계·실측은 같은 폴더의 하위 문서
3. **날짜가 있는 회의인가?** (참석자·결정·액션이 있는 것) → `meetings/YYYY-MM-DD 제목.md`. 짧은 싱크는 daily 의 `## 회의` 한 줄
4. **확정된 결정인가?** (무엇을·왜·기각한 대안·누가) → `decisions/YYYY-MM-DD 제목.md`. 아직 열려 있으면 결정이 아니라 프로젝트 README 의 `## 열린 문제`
5. **틀렸다가 실측으로 정정한 것인가?** → `lessons/YYYY-MM-DD 규칙 문장.md` (형식은 `/log` 5절)
6. **오늘 한 일인가?** → `daily/YYYY-MM-DD.md` 의 프로젝트 헤딩 아래
7. **어디에도 안 맞는다** → 일단 오늘 daily 의 `## 기타`. 같은 종류가 세 번 쌓이면 폴더를 새로 만든다

## 페이지를 만들 조건

- **사람**: 다시 볼 사람만. 한 번 스친 이름은 만들지 않는다.
- **프로젝트**: daily 에 같은 프로젝트 헤딩이 세 번 넘게 나오면.
- 만들 때는 아래 모양 그대로. 빈 절은 두지 않는다.

```markdown
---
type: person            # 또는 project
aliases: [영문이름, 닉네임]
---
# 이름

한두 문장 요약 — 누구인지 / 무엇인지.

## 지금
- 역할·담당 (현재 사실만. 바뀌면 덮어쓴다)

## 타임라인
- 2026-09-30 — 한 줄 사실 ([[2026-09-30]])
```

**지금** 은 현재 참인 것만 두고 덮어쓴다. **타임라인** 은 추가만 한다 — 옛 사실은 여기 남는다.

## 정정 절차 (새 정보가 옛 정보를 뒤집을 때)

**새 사실은 덮고, 옛 사실은 지우지 말고 표시한다.** 지우면 "언제 왜 바뀌었나"가 사라지고, 안 지우면 다음 세션이 옛것을 계속 믿는다.

1. 새 사실을 정본 자리에 쓴다. 엔티티면 `## 지금` 을 덮고 타임라인에 `YYYY-MM-DD — 정정: 종전 X → Y (근거 링크)`.
2. 옛 decision·lesson 페이지면 frontmatter 에 `status: superseded`(폐기) 또는 `status: narrowed`(조건부로만 유효) + `superseded_by: "[[새 페이지]]"`, 본문 첫 줄에 `> **[YYYY-MM-DD 폐기]** 무엇이 바뀌었나 + [[새 페이지]]`.
3. 퍼진 사본을 찾는다: `grep -rIl "<옛 사실 키워드>" ~/notes ~/.claude/projects/*/memory/`. 한 곳만 고치면 나머지가 계속 이긴다.
4. Claude 메모리 파일도 같은 방식으로 표시하고, 그 워크스페이스 `MEMORY.md` 인덱스 줄도 고친다 — 세션이 매번 읽는 건 인덱스다.

## 헷갈리는 경계

- **lesson vs decision**: 깨진 것에서 배웠으면 lesson, 선택지 중 하나를 골랐으면 decision. 둘 다일 수 있다.
- **daily vs meetings**: 결정·액션이 없으면 daily 한 줄로 충분하다.
- **이름**: 파일명은 한글 그대로(`홍길동.md`), `aliases:` 에 영문·닉네임·메일 로컬파트. 프로젝트 폴더는 영문 slug.

## 쓰지 않는 것

비밀번호·토큰·고객 개인정보·남의 인사 정보는 어느 폴더에도 쓰지 않는다. 사람 페이지는 **업무상 사실**만 — 평가·험담은 적지 않는다.
